# Протокол v2

Источник истины:

- [`shared/ts/protocol.ts`](../shared/ts/protocol.ts) — типы, способности, константы;
- [`shared/csharp/Protocol.cs`](../shared/csharp/Protocol.cs) — C#-зеркало для мода.

При изменении протокола **сначала** правь TypeScript, затем C#. Версия должна совпадать
на relay, в моде и в клиенте.

## 1. Что изменилось в v2

- Призрак летает в 3D: камера передаёт `pitch`, карта — высоту стен и уровень пола.
- Появилось сообщение `preview`: браузер заранее показывает намерение, а мод рисует
  голограмму в мире игры.
- Бочка летит по явному направлению (`dirX`, `dirZ`) и силе броска (`power`).
- Удалены хаос и способность «Шёпот». Остались пять способностей.
- Удалены аргументы `behind` и `distance`: точка способности всегда приходит из прицела.
- `MapWall` теперь хранит центр по Y, `MapData` — `floorY`.

## 2. Транспорт

| Параметр | Значение |
| --- | --- |
| Транспорт | WebSocket, текстовые фреймы |
| Endpoint | `ws://<host>:8080/ws` или `wss://<host>/ws` |
| Формат | JSON, одно сообщение — один объект с полем `t` |
| Максимальный размер | relay — 2 МБ, мод — 4 МБ |
| Handshake | первое сообщение обязательно `hello`, таймаут 10 с |
| Версия | `2` (`PROTOCOL_VERSION`) |
| Сжатие | отключено (`perMessageDeflate: false`) |
| Ping | WebSocket ping relay каждые 30 с; прикладной `ping`/`pong` — по желанию |

Relay принимает upgrade только по пути `/ws`. Остальные пути отдают HTTP или 404.

## 3. Конверт

У каждого сообщения есть строковое поле `t`. Остальные поля зависят от типа.

```json
{ "t": "ping", "ts": 1760000000000 }
```

Направления:

- `game → relay` — игра;
- `relay → game` — команды, камера, preview, чат;
- `ghost → relay` — команды, камера, preview, чат, ping;
- `relay → ghost` — состояние, карта, события, ack;
- `relay → all` — `peer`, `chat`.

## 4. Handshake

```
Клиент                          Relay
  │                               │
  │──── hello ───────────────────►│  проверка t, protocol, room, role, token
  │                               │
  │◄─── welcome ──────────────────│  peerId, список участников
  │◄─── [map] ────────────────────│  если призрак и есть кэш
  │◄─── [snapshot] ───────────────│  если призрак и есть кэш
  │                               │
  │◄─── peer(joined) ─────────────│  остальным участникам
```

### `hello`

```json
{
  "t": "hello",
  "protocol": 2,
  "room": "TEST",
  "role": "ghost",
  "name": "Аня"
}
```

| Поле | Тип | Обяз. | Описание |
| --- | --- | --- | --- |
| `protocol` | number | да | Должен быть равен `2`. |
| `room` | string | да | 4–8 символов `A–Z`, `0–9`; приводится к верхнему регистру. |
| `role` | `"game"` \| `"ghost"` | да | Роль участника. |
| `token` | string | нет | Только для `game`, если на relay задан `RELAY_TOKEN`. |
| `name` | string | нет | До 24 символов, очищается от управляющих символов. |

### `welcome`

```json
{
  "t": "welcome",
  "protocol": 2,
  "room": "TEST",
  "peerId": "p_1a2b3c4d",
  "peers": [{ "id": "p_9f8e7d6c", "role": "game", "name": "VR" }],
  "serverTime": 1760000000000
}
```

### `peer`

```json
{ "t": "peer", "event": "joined", "peerId": "p_1a2b3c4d", "role": "ghost", "name": "Аня" }
```

`event` — `joined` или `left`.

### `error`

```json
{ "t": "error", "code": "bad_token", "message": "Неверный токен relay." }
```

## 5. Состояние игры

### `snapshot` (game → relay → ghost)

Отправляется с частотой `SnapshotHz` (по умолчанию 10 Гц).

```json
{
  "t": "snapshot",
  "seq": 412,
  "ts": 1760000000123,
  "scene": "Level_1",
  "player": {
    "pos": { "x": 1.2, "y": 0.1, "z": -3.4 },
    "yaw": 1.57,
    "vel": { "x": 0.3, "y": 0, "z": -0.8 },
    "hp": 87.5,
    "alive": true
  },
  "ghost": {
    "pos": { "x": 1.2, "y": 2.6, "z": -9.4 },
    "yaw": 1.57,
    "manifested": false,
    "stunned": false
  },
  "enemies": [
    { "id": 7, "kind": "runner", "pos": { "x": 4, "y": 0, "z": 2 }, "hp": 45, "state": "chase", "ghost": false }
  ],
  "props": [
    { "id": 3, "kind": "barrel", "pos": { "x": -2, "y": 0, "z": 5 }, "mass": 20 }
  ],
  "energy": 62.4,
  "maxEnergy": 100,
  "cooldowns": { "spawn_enemy": 3.4, "manifest": 12.1 },
  "stats": { "scares": 4, "kills": 2, "spawns": 5, "barrels": 1, "sessionTime": 143.2 }
}
```

| Поле | Описание |
| --- | --- |
| `seq` | Монотонный номер снапшота. |
| `ts` | Unix-время в миллисекундах. |
| `scene` | Имя активной сцены Unity. |
| `player.yaw` | Радианы, направление взгляда в плоскости XZ. |
| `player.vel` | Сглаженная скорость игрока. |
| `player.hp` / `alive` | Здоровье и признак жизни. |
| `ghost.pos` | Полная 3D-позиция камеры призрака (или позиция за игроком, если камера ещё не пришла). |
| `ghost.yaw` | Горизонтальный поворот камеры призрака. |
| `ghost.manifested` | Активна ли манифестация. |
| `ghost.stunned` | Зарезервировано; сейчас всегда `false`. |
| `enemies` | До 60 ближайших живых врагов. |
| `enemies[].state` | `idle`, `chase`, `attack`, `dead` — вычисляется по дистанции до игрока. |
| `props` | До 30 взрывных бочек. |
| `energy` / `maxEnergy` | Текущая и максимальная энергия. |
| `cooldowns` | Оставшиеся секунды по каждой способности. |
| `stats` | Счётчики сессии. |

Хаоса в снапшоте больше нет.

### `map` (game → relay → ghost)

```json
{
  "t": "map",
  "scene": "Level_1",
  "bounds": { "minX": -34, "minZ": -34, "maxX": 34, "maxZ": 34 },
  "floorY": 0,
  "walls": [
    { "x": 0, "y": 2, "z": 30, "w": 60, "h": 4, "d": 1 }
  ],
  "image": null
}
```

| Поле | Описание |
| --- | --- |
| `bounds` | Прямоугольник карты в мировых координатах. |
| `floorY` | Мировой Y пола, ниже которого призраку не стоит опускаться. |
| `walls` | Прямоугольные препятствия (до 700). `x/y/z` — центр, `w/h/d` — размеры по X/Y/Z. |
| `image` | Зарезервировано под картинку; в v2 `null`. |

Карта приходит при подключении и при смене сцены. Relay кэширует последнюю и отдаёт
новому призраку.

### `event` (game → relay → ghost)

```json
{ "t": "event", "kind": "enemy_spawned", "data": { "kind": "runner", "x": 4, "z": 2 }, "ts": 1760000000123 }
```

| `kind` | `data` |
| --- | --- |
| `enemy_spawned` | `kind`, `x`, `z` |
| `barrel_exploded` | зарезервировано; мод отправляет `scare` с `type: "barrel"` |
| `player_hit` | `damage`, `hp` |
| `player_died` | `hp` |
| `ghost_stunned` | зарезервировано |
| `manifest_start` | `x`, `y`, `z` |
| `manifest_end` | — |
| `scare` | `type`: `barrel`, `telekinesis`, `poltergeist`; координаты и доп. поля |
| `scene_changed` | `scene` |
| `info` | произвольные данные |

### `toast` (game → relay → ghost)

```json
{ "t": "toast", "text": "Игрок потерял 20 HP", "level": "warn" }
```

`level` — `info`, `warn` или `good`.

### `pong`

Ответ на `ping`, возвращает тот же `ts`.

## 6. Preview (намерение призрака)

### `preview` (ghost → relay → game)

Браузер отправляет preview примерно 10 раз в секунду, пока призрак целится и способность
готова. Мод рисует в мире полупрозрачную голограмму: врага, бочку со стрелкой, точку
телекинеза или полтергейста. VR-игрок видит, что сейчас произойдёт.

```json
{
  "t": "preview",
  "active": true,
  "ability": "throw_barrel",
  "pos": { "x": 4.2, "y": 0.0, "z": -8.1 },
  "dir": { "x": 0.0, "y": 0.0, "z": 1.0 },
  "kind": "grunt",
  "ts": 1760000000000
}
```

| Поле | Описание |
| --- | --- |
| `active` | `true` — показывать голограмму, `false` — убрать. |
| `ability` | `spawn_enemy`, `throw_barrel`, `telekinesis`, `poltergeist` или `null`. |
| `pos` | Точка применения в мире. Мод прижимает её к полу/поверхности. |
| `dir` | Только для `throw_barrel`: горизонтальное направление полёта, нормализуется relay/модом. |
| `kind` | Только для `spawn_enemy`: тип врага. |

Правила:

- при `active = false` остальные поля игнорируются;
- мод сам снимает голограмму через 1.6 с без нового preview;
- после любого каста, при кулдауне, разрыве соединения или смене сцены мод голограмму
  убирает;
- стрелка у бочки — часть голограммы, поэтому исчезает в момент броска;
- preview не расходует энергию и не создаёт объектов.

Relay проверяет, что `ability` входит в набор, координаты конечны и ограничены ±10 000,
а `dir` нормализуется. Неизвестные поля отбрасываются.

## 7. Команды

### `cmd` (ghost → relay → game)

```json
{
  "t": "cmd",
  "id": "c_17",
  "ability": "throw_barrel",
  "args": { "x": 4.2, "y": 0.0, "z": -8.1, "dirX": 0.0, "dirZ": 1.0, "power": 14, "fuse": 3 },
  "ts": 1760000000000
}
```

| Поле | Описание |
| --- | --- |
| `id` | Уникальный ID команды (до 64 символов), по нему приходит `ack`. |
| `ability` | Один из фиксированных ID. |
| `args` | Параметры; неизвестные поля отбрасываются. |
| `ts` | Время отправки, мс. |

### `ack` (game → relay → ghost)

```json
{ "t": "ack", "id": "c_17", "ok": true, "energy": 37.4, "cooldown": 4 }
```

При ошибке:

```json
{ "t": "ack", "id": "c_17", "ok": false, "error": "cooldown" }
```

`cooldown` — длительность кулдауна в секундах при успехе.

### Аргументы `CmdArgs`

| Поле | Тип | Где используется | Смысл |
| --- | --- | --- | --- |
| `kind` | string | `spawn_enemy` | `grunt`, `runner`, `shooter`, `heavy`. В v2 — метка для UI и статистики. |
| `x`, `y`, `z` | number | точечные способности | Мировые координаты точки прицела. |
| `dirX`, `dirZ` | number | `throw_barrel` | Горизонтальное направление полёта; мод нормализует. |
| `targetId` | number | `telekinesis` | ID врага из снапшота; иначе мод ищет ближайшее тело. |
| `power` | number | `throw_barrel`, `telekinesis` | Сила/скорость, ограничивается модом. |
| `duration` | number | `poltergeist`, `manifest` | Секунды; ограничивается модом. |
| `fuse` | number | `throw_barrel` | Зарезервировано: задержка определяется игрой. |
| `mode` | string | — | Зарезервировано. |

Полей `behind` и `distance` в v2 нет. Если координаты не переданы, мод использует позицию
игрока (для манифестации — позицию камеры призрака).

### Способности

| ID | Название | Цена | Кулдаун | Наведение | Клавиша |
| --- | --- | ---: | ---: | --- | --- |
| `spawn_enemy` | Спавн врага | 25 | 8 с | точка | 1 |
| `throw_barrel` | Взрывная бочка | 15 | 4 с | точка | 2 |
| `telekinesis` | Телекинез | 10 | 2 с | сущность | 3 |
| `poltergeist` | Полтергейст | 8 | 6 с | точка | 4 |
| `manifest` | Манифестация | 30 | 20 с | на себя | 5 |

Минимального хаоса нет. Манифестация доступна, как только хватает энергии и кулдаун
восстановился.

### Бочка

- Точка `x/y/z` — место появления бочки.
- Направление `dirX/dirZ` — горизонтальный вектор; мод нормализует его и добавляет
  небольшой подъём, чтобы бочка летела по дуге.
- `power` — скорость, мод ограничивает диапазоном 4–30; браузер по умолчанию отправляет 14.
- `fuse` пока не управляет задержкой: используется штатное поведение `ExplodingBarrel`.
- После броска голограмма и стрелка исчезают, а бочка становится обычным объектом игры.

## 8. Камера, чат, ping

### `camera` (ghost → relay → game)

```json
{
  "t": "camera",
  "pos": { "x": 1.2, "y": 2.6, "z": -9.4 },
  "yaw": 1.57,
  "pitch": -0.2,
  "ts": 1760000000000
}
```

Клиент отправляет её при движении и примерно раз в 90 мс. `pos` — полная 3D-позиция
камеры, `yaw` — горизонтальный поворот, `pitch` — наклон. Мод использует позицию для
манифестации и `ghost.pos` в снапшоте; `pitch` передаётся для будущих 3D-эффектов.

### `chat` (any → relay → others)

```json
{ "t": "chat", "from": "ghost", "text": "Бу!", "ts": 1760000000000 }
```

Relay пересылает чат всем, кроме отправителя. Мод показывает сообщение призрака через
`PlayerTextOverlay`. Это отдельный чат, а не способность «Шёпот».

### `ping` / `pong`

```json
{ "t": "ping", "ts": 1760000000000 }
{ "t": "pong", "ts": 1760000000000 }
```

Мод отправляет `ping` раз в 5 секунд. Relay также делает WebSocket ping каждые 30 секунд.

## 9. Проверки и ошибки

### 9.1. Relay (мягкие проверки)

Relay хранит последний снапшот и по нему проверяет:

- `energy`: если энергии меньше стоимости + 0.5, команда отклоняется;
- `cooldown`: если по снапшоту осталось больше 250 мс, команда отклоняется;
- роль: `cmd`, `camera` и `preview` может отправлять только `ghost`;
- наличие игры в комнате;
- rate limit: 80 сообщений/с, burst 160;
- санитайзинг аргументов: числа в ±10 000, текст до 180 символов, имя до 24, чат до 240.

Relay отвечает `ack` с ошибкой, не пересылая команду игре.

### 9.2. Мод (жёсткие проверки)

Мод проверяет те же условия по своим значениям, а затем пытается выполнить действие.
Даже если relay пропустил команду, мод может ответить:

| `error` | Причина |
| --- | --- |
| `unknown_ability` | Способность не входит в набор v2. |
| `cooldown` | Кулдаун ещё не истёк. |
| `not_enough_energy` | Энергии меньше стоимости. |
| `failed` | Игровой API не смог выполнить действие (нет префаба, объект исчез и т.п.). |

### 9.3. Коды ошибок handshake и соединения

| `code` | Когда |
| --- | --- |
| `bad_hello` | Первое сообщение не `hello` или не JSON-объект. |
| `protocol_mismatch` | Версия протокола не равна 2. |
| `bad_room` | Код комнаты не 4–8 символов `A–Z/0–9`. |
| `bad_token` | Игра не прислала или прислала неверный `RELAY_TOKEN`. |
| `room_full` | В комнате уже есть игра или два призрака. |
| `handshake_timeout` | `hello` не пришёл за 10 секунд. |
| `bad_message` | Сообщение не JSON-объект или без `t`. |
| `unknown_message` | Неизвестный `t`. |
| `rate_limited` | Превышен лимит сообщений. |
| `bad_role` | Призрак пытается делать то, что можно только игре, или наоборот. |
| `bad_id` | Пустой `cmd.id`. |
| `no_game` | В комнате нет игры. |

Коды закрытия WebSocket: `4000` handshake timeout, `4001` protocol mismatch, `4002` bad
room, `4003` bad token, `4004` room full.

## 10. Пример полного обмена

```
ghost → relay: hello(ghost, TEST)
relay → ghost: welcome
relay → ghost: map (из кэша)
relay → ghost: snapshot (из кэша)
ghost → relay: camera(pos, yaw, pitch)
ghost → relay: preview(throw_barrel, pos, dir)
relay → game:  preview(...)
ghost → relay: cmd(throw_barrel, pos, dir, power)
relay → game:  cmd(...)
game  → relay: ack(id, ok=true, energy=75, cooldown=4)
relay → ghost: ack(...)
game  → relay: event(scare, type=barrel)
relay → ghost: event(...)
game  → relay: snapshot (10 Гц)
relay → ghost: snapshot
```

## 11. Совместимость и изменения

- Версия протокола — целое число. Несовпадение версий закрывает соединение.
- Новые необязательные поля можно добавлять без смены версии, если старые клиенты их
  игнорируют. Удаление/переименование полей требует новой версии.
- Способности — закрытый набор. Новая способность требует обновления:
  1. `AbilityId` и `ABILITIES` в `shared/ts/protocol.ts`;
  2. `Abilities.All` в `shared/csharp/Protocol.cs`;
  3. обработчика в `GhostDirector.HandleCommand`;
  4. реализации в `GameBridge`;
  5. карточки/горячей клавиши в `ghost-app`;
  6. проверки в relay (если нужны особые правила).
- Баланс (цена/кулдаун) дублируется в TS и C#. При изменении проверяй оба файла.
